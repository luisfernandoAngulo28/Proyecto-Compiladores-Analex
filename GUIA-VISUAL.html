Las 4 clases del proyecto — qué hace cada una

Token.java — El "sobre" del token

Guarda dos números: el nombre del token (nom) y su atributo (atr).

private int nom;  // qué tipo es
private int atr;  // valor adicional

// Ejemplo:
nom = Token.NUM   // es un número
atr = 30          // atributo fijo

Cinta.java — La cinta de chars

Serializa el programa fuente char a char. Los 3 métodos que usa el Analex:

M.cc()       // leer char actual
M.avanzar()  // mover cabezal →
M.init()     // rebobinar al inicio

// Chars especiales:
Cinta.EOF  = 0   // fin de archivo

TPC — Tabla de Palabras Clave (OBLIGADO por el enunciado)

La TPC es un HashMap<String, Integer> privado dentro de la clase Analex. Mapea el lexema exacto (en minúsculas) al número del token correspondiente.

¿Cómo funciona?
Al terminar de leer un ID (estado 2), antes de devolver <ID,-1> se consulta la TPC. Si el lexema está → devuelve la palabra clave. Si no → es un ID. 
// Consulta de la TPC en el estado 2:
if (TPC.containsKey(ac)) {
    int nom = TPC.get(ac);
    R.set(nom, atr);        // es KW
} else {
    R.set(Token.ID, -1);   // es ID
}
Case-Sensitive activo: la TPC tiene las claves en minúsculas exactas. "while" → WHILE. "While" → ID.

Estados del DT — el método dt()

El método dt() implementa el Diagrama de Transición. Siempre empieza en estado 0, lee char a char, y cuando llega a un estado final devuelve el token y para.

Regla de retroceso: cuando el DT llega al estado final por "Otro", el carácter que disparó la transición NO se consume (no llamamos M.avanzar()). Ese char pertenece al siguiente token.

Preguntas frecuentes del docente:

¿Qué es la TPC?

Un HashMap<String,Integer> privado en Analex. Mapea lexema → token. Se consulta al final del estado 2 para distinguir ID de palabras clave.

¿Por qué NUM tiene atributo 30?

Lo define el enunciado: <NUM, 30>. El 30 es el atributo fijo, no el valor del número. Así el Parser sabe que es un NUM sin necesitar la TSID.

¿Qué hace el estado 7?

Leímos /. Si sigue / → comentario de línea (q8). Si sigue * → comentario de bloque (q9). Si es otro char → DIV.

¿Por qué case-sensitive?

El enunciado original era case-insensitive, pero en la pizarra de defensa se pidió cambiar a case-sensitive. Se quitó toLowerCase() del estado 2.
